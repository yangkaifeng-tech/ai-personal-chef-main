# 网约车后台与 AI 管家需求规格

## 范围

在现有 FastAPI 项目中新增一个前后端分离的后台管理系统。前端使用 Vue 3、Vite、TypeScript、Element Plus，目录为 `frontend/`。后端继续使用 FastAPI，并使用 PostgreSQL 保存业务数据。系统包含真实登录、RBAC 权限、司机管理、车辆管理、调度管理占位页、AI 管家页和权限管理页。

## 非目标

- 本阶段不实现调度管理的完整业务 CRUD。
- 本阶段不实现短信验证码、第三方登录、真实支付或地图调度。
- 本阶段不替换当前 LangChain/LangGraph Agent 逻辑，只把现有私厨管家页面迁入后台系统的“AI管家”菜单。
- 本阶段不实现复杂组织架构、多租户公司隔离和数据权限行级策略。

## 用户故事

1. 作为管理员，我希望能用账号密码登录后台，以便进入系统管理页面。
2. 作为管理员，我希望能维护人员、角色、菜单和按钮权限，以便控制不同用户能访问哪些页面和操作。
3. 作为管理员，我希望能给用户分配角色，以便用户自动获得角色对应的菜单和按钮权限。
4. 作为运营人员，我希望能管理司机资料，以便新增、查询、编辑和删除司机。
5. 作为运营人员，我希望能管理车辆资料，以便新增、查询、编辑和删除车辆。
6. 作为后台用户，我希望能在“AI管家”菜单使用现有私厨管家，以便在后台内继续使用 AI 对话能力。

## 功能需求

### 认证

- 当用户提交账号密码时，系统应校验用户名和密码。
- 当登录成功时，系统应返回 JWT token、用户信息、菜单权限和按钮权限。
- 当请求受保护接口时，系统应校验 JWT token。
- 当 token 无效或过期时，系统应拒绝请求并返回 401。

### 权限

- 当用户登录后，系统应只返回该用户角色拥有的菜单。
- 当用户进入页面时，前端应只渲染后端返回的授权菜单。
- 当页面包含按钮操作时，前端应根据按钮权限 code 控制按钮显示。
- 当后端收到新增、编辑、删除等受控操作时，系统应校验当前用户是否拥有对应按钮权限。

### 权限管理

- 当管理员进入“权限管理/人员管理”时，系统应支持人员的列表、创建、编辑、删除和角色分配。
- 当管理员进入“权限管理/角色管理”时，系统应支持角色的列表、创建、编辑、删除。
- 当管理员维护角色时，系统应支持给角色分配菜单和按钮。
- 当管理员进入“权限管理/菜单管理”时，系统应支持菜单的列表、创建、编辑、删除。
- 当管理员进入“权限管理/按钮管理”时，系统应支持按钮的列表、创建、编辑、删除，并关联到菜单页面。

### 网约车管理

- 当用户拥有司机管理菜单权限时，系统应允许访问司机管理页面。
- 当用户拥有司机新增、编辑、删除按钮权限时，系统应显示并允许执行对应操作。
- 当用户拥有车辆管理菜单权限时，系统应允许访问车辆管理页面。
- 当用户拥有车辆新增、编辑、删除按钮权限时，系统应显示并允许执行对应操作。
- 当用户访问调度管理时，系统应展示占位页面，提示该模块后续实现。

### AI 管家

- 当用户拥有 AI 管家菜单权限时，系统应允许访问私厨管家页面。
- 当用户在 AI 管家发送消息时，系统应调用现有 FastAPI AI 对话接口。
- 当用户刷新页面时，系统应能基于当前用户和会话恢复历史消息。

## 数据需求

- 系统应使用 PostgreSQL 保存用户、角色、菜单、按钮、司机、车辆和 AI 会话业务消息。
- LangGraph checkpoint 默认保存到同一个 PostgreSQL 数据库。
- checkpoint 应支持通过配置切换为 SQLite。
- 系统应提供初始化默认管理员、默认角色、默认菜单和默认按钮权限的能力。

## 初始菜单

- 网约车管理
- 司机管理
- 车辆管理
- 调度管理
- AI管家
- 私厨管家
- 权限管理
- 人员管理
- 角色管理
- 菜单管理
- 按钮管理

## 初始角色

- 超级管理员：拥有所有菜单和按钮权限。
- 运营管理员：拥有网约车管理、司机管理、车辆管理、调度管理、AI管家相关权限。
- 普通客服：拥有司机、车辆和 AI 管家的查看权限。

## 验收标准

- 当系统首次启动且数据库为空时，系统应初始化默认管理员账号、默认角色、菜单和按钮。
- 当超级管理员登录时，系统应展示所有菜单和所有按钮。
- 当运营管理员登录时，系统应看不到“权限管理”菜单。
- 当普通客服登录时，系统应看不到新增、编辑、删除按钮。
- 当无 token 请求司机或车辆接口时，系统应返回 401。
- 当无权限用户调用删除司机接口时，系统应返回 403。
- 当有权限用户新增司机时，系统应把司机数据写入 PostgreSQL 并在列表中展示。
- 当有权限用户编辑车辆时，系统应更新 PostgreSQL 中对应车辆数据。
- 当有权限用户删除车辆时，系统应从列表中移除该车辆。
- 当用户进入“AI管家/私厨管家”时，系统应展示迁移后的 Vue 版私厨对话页面。
- 当用户在 AI 管家继续对话时，系统应保存业务消息到 PostgreSQL，并让 LangGraph checkpoint 保存运行状态。
- 当 `CHECKPOINT_BACKEND=sqlite` 时，系统应把 checkpoint 写入 SQLite 文件。
- 当前端执行构建时，Vue 项目应能通过类型检查和生产构建。
- 当前端登录、菜单渲染、司机 CRUD、车辆 CRUD、AI 管家页面流式对话通过浏览器冒烟测试时，改造才算完成。
