技能树

你应该怎么学这个项目

前端工程师看 Agent 项目时，不要先陷进模型名和参数。先把它当成一个“异步后端编排系统”：输入、状态、工具、模型、输出流，这五件事理清以后，再看 LangChain 的抽象就会顺很多。

输入层 浏览器收集文字和图片，图片先上传 OSS，再把 URL 发给后端。
服务层 FastAPI 暴露 `/api/v1/chat/stream`，用 StreamingResponse 持续吐 token。
Agent 层 LangChain 创建 Agent，把模型、工具、系统提示词和记忆组合起来。
状态层 LangGraph SQLite Checkpointer 记录 thread_id 对应的对话历史。

核心概念卡片

Python 对你来说是什么

这里的 Python 主要不是算法语言，而是后端编排语言：定义接口、读环境变量、调用 SDK、处理异步请求、组织模型调用。

类比前端：FastAPI 路由像 Next.js API Route；Pydantic Model 像运行时 DTO 校验；async 函数像浏览器里的 Promise 链。

LangChain Agent 是什么

Agent 不是一个神秘实体。它本质上是“模型 + 工具列表 + 系统提示词 + 状态管理”的运行循环。

模型负责判断下一步；工具负责连接外部能力；checkpointer 负责保存上下文。

工具调用是什么

TavilySearch 被注册成工具后，模型可以输出 tool call，LangChain 执行工具，再把工具结果送回模型继续生成。

注意：模型说“我将调用工具”不等于真的调用。要看日志里的 ToolMessage 或实际 HTTP 请求。

# src/app/api/v1/oss.py
client = oss.Client(cfg)

@router.get("/oss/presign")
def chat_endpoint(filename: str):
    pre_result = client.presign(
        oss.PutObjectRequest(bucket=OSS_BUCKET, key=filename, content_type=content_type),
        expires=timedelta(seconds=3600)
    )
    return {
        "uploadUrl": pre_result.url.strip('"'),
        "contentType": content_type,
        "accessUrl": f"https://{OSS_BUCKET}.{OSS_ENDPOINT}/{filename}"
    }

学习重点：
1. 后端不直接接收图片文件，而是签一个临时上传地址。
2. 浏览器拿 uploadUrl 直接 PUT 到 OSS。
3. accessUrl 再作为图片地址传给聊天接口。

这个项目最值得学的坑

这些比“能跑起来”更重要，因为真实 Agent 开发大多卡在边界和状态上。

图片 URL 不等于模型能访问

浏览器能打开、后端能 curl，不代表模型服务端能下载。OSS 默认域名、ACL、强制下载、防盗链、签名过期都可能影响模型侧下载。

方案稳定性代价
直接传 OSS URL依赖外部可访问性链路简单，但调试不稳定
后端转 Base64更稳定请求体更大，后端多一次下载
自定义域名/CDN适合生产需要配置域名、缓存、权限

历史记忆会污染新请求

LangGraph 会把 thread_id 下的历史带入下一轮。如果历史里残留旧图片消息，即使你新代码已经改成 Base64，模型仍可能收到旧 URL 并报错。

本项目用了 `thread_id:agent-text` 隔离 Agent 文本记忆，避免旧的多模态消息继续进入后续请求。

“说调用工具”不等于真的调用

Agent 的关键证据不是最终文本，而是运行日志里的 tool call、ToolMessage 或外部服务请求。现在代码里已经加了 `[工具调用中]` 和 `[工具调用结果]` 日志。

模型会编造链接

当提示词要求“参考图片”但搜索结果没有真实图片 URL 时，模型可能输出 `example.com`。后端要约束，前端也要过滤占位链接。

一次完整请求的运行时顺序

1

用户选择图片

`app.js` 创建本地预览 blob，同时请求 `/api/v1/oss/presign`。

2

浏览器上传 OSS

浏览器使用后端返回的 `uploadUrl` 执行 PUT 上传，成功后得到 `accessUrl`。

3

发起聊天流

前端 POST `/api/v1/chat/stream`，提交 `message`、`image_url`、`thread_id`。

4

后端视觉识别

`identify_ingredients()` 下载图片并转成 Base64，调用视觉模型得到食材清单。

5

Agent 生成推荐

Agent 收到文字化食材清单，理论上可调用 Tavily，再把结果整理成菜谱。

6

前端流式渲染

`ReadableStream` 持续读取 chunk，增量更新 assistant 气泡。
